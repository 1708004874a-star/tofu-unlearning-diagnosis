8○

Gate 2 — RMU 阳性对照顺序不能调 ②：gate 排在被 gate 的东西后面等于没 gate

做什么

RMU 两项 loss 都建在 model.layers.7 的输出激活上，计算图止于第 7 层 → 8–15 层的 .grad 是 None，优化器（paged_adamw_32bit）整个跳过，weight_decay 也够不着。这些层的 Δθ 是精确的 0。

判据

① 8–15 层 Δθ 严格为 0（逐元素比 state_dict，不用评测）② 这些层的恢复量严格为 0 ③ 显著的层全部落在 0–7 层内 ④ 0–7 层里至少 1 层显著。

产物

四条判据的逐条结果。顺带查 model.norm——它也在计算图下游，Δθ 同样应为 0，判据表里没列，一起查不花钱。

分支前三条任一失败才是真停机（restore 代码有 bug 或评测噪声底太高）。第 4 条失败改走累积换回：0–7 整体 → 二分（0–3 / 4–7）→ 再二分，多 4–6 次评测——第 7 步已从机械上证明管道可用，此时只可能是单层探针不够灵敏，那是结论不是故障。
一道已知答案的考题　Llama-3.2-1B 共 16 层，判据是二值的、不用挑阈值
0–7 层：RMU 改动区，压制点必须全落在这里 8–15 层 + model.norm：Δθ 精确为 0，换回必须毫无变化
附带确定性检查：8–15 层那 8 次 restoration 跑的其实是同一个模型，贪心解码下预期逐位相同、离散度为 0。非 0 说明评测本身不确定，影响所有后续比较。

01

评测按 output_dir 缓存，只认目录不认模型静默

overwrite=False（默认）时先读目录下已有的 TOFU_EVAL.json，逐指标 skip already evaluated。换了权重指向同一目录，它会把上一个变体的结果当成已算过返回。扫层／移植／relearning 的每个变体必须各用自己的 output_dir。同一条规则的另一面：这就是断点续跑机制——目录不复用的话，中断后原样重跑会自动跳过已算完的指标。但 flush 发生在每个顶层指标算完之后，model_utility 内部那九个子指标是一个整体，中途断掉整个重来（约 45 分钟）。

src/evals/base.py · flush 在 :109-110
02

查 requires_grad 永远验不出 RMU 改了哪些参数

RMU.create_optimizer() 最后一行是 _freeze_all_params(model, True)——optimizer 构造完之后所有参数的 requires_grad 又被设回 True。要验只能靠 regex 预检 + 比对 state_dict。

privleak 会在缺 retain 日志时编出一个正常数字静默

漏传 retain_logs_path 时 forget_quality 返回 None（至少看得见）；holdout_split 与 forget_split 不匹配则 MIA 类全废。真正危险的是 privleak：没有 retain 日志时它不返回 None，而是 except 掉、回落到 ref_value: 0.5，照常算出一个看起来完全正常的百分数。它是"遗忘不足"轴的指标之一，这个假数会直接进报告。

13

两项 loss（forget 的激活-control vector MSE、retain 的 EMBED_DIFF）都建在 model.layers.7 的输出激活上，计算图止于第 7 层 → 8–15 层的 .grad 是 None。优化器不是 torch AdamW 而是 paged_adamw_32bit，跳过逻辑相同（bitsandbytes/optim/optimizer.py:284 同样 if p.grad is None: continue），weight_decay: 0.01 也够不着。这是 Gate 2 整个阳性对照的理论依据。补充：model.norm（第 15 层之后的 final RMSNorm）同样在计算图下游，Δθ 也应为 0，判据表没列它，顺手一起查。
